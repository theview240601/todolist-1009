# 계획서 모음

이 앱을 만들면서 세운 계획을 순서대로 모아 둔 문서예요.

---

## 1차 — 업무·프로젝트 투두리스트 만들기

### 왜 만드나요
- 내 컴퓨터에서 나 혼자 쓰는 **업무·프로젝트용 할 일 목록**이 필요하다.
- 배포·서버·데이터베이스는 쓰지 않는다. 파일을 더블클릭하면 브라우저에서 바로 열린다.
- 새로고침하거나 브라우저를 껐다 켜도 목록이 남도록 **브라우저 저장소(localStorage)** 에 저장한다.
- 질문 답변: 용도 = 업무·프로젝트 / 붙일 정보 = 마감일·중요도·분류·메모 / 디자인 = 깔끔한 흰 화면

### 화면 구성
1. **맨 위**: 제목 "내 업무 할 일" + 오늘 날짜 + "남은 일 N개 / 완료 N개 / 마감 지남 N개"
2. **왼쪽 칸 – 프로젝트(분류) 목록**
   - "전체", 그리고 내가 만든 프로젝트 이름들
   - 프로젝트 추가 / 이름 바꾸기 / 삭제 (삭제할 땐 "정말 지울까요?" 물어봄)
   - 누르면 그 프로젝트 할 일만 보임
3. **할 일 입력칸**: 제목(필수), 프로젝트, 마감일, 중요도(높음·보통·낮음), 메모. 엔터로도 추가.
4. **할 일 목록**
   - 체크박스로 완료 표시 → 줄이 그어지고 목록 아래로
   - 마감일 옆에 "D-3", "오늘 마감", "2일 지남" 표시. 마감 지난 일은 눈에 띄는 색
   - 연필 버튼 = 수정, 휴지통 버튼 = 삭제 (확인 후)
5. **보기 옵션**: 정렬(마감일·중요도·최근 추가), 보기(전체·할 일만·완료만), 검색(제목·메모), 완료한 일 지우기

### 저장 방식
- 할 일과 프로젝트를 localStorage 한 칸(`work-todo-v1`)에 저장한다.
- 마지막으로 고른 프로젝트·정렬·보기는 다른 칸(`work-todo-ui-v1`)에 저장한다.
- 바뀔 때마다 바로 저장 → 새로고침·브라우저 재시작 후에도 그대로 남는다.
- 처음 열면 프로젝트 "일반" 하나만 만들어 둔다.

### 결과
- `index.html`, `style.css`, `app.js`, `README.md` 네 파일로 완성.
- Git으로 기록을 남기고, 나중에 GitHub 공개 저장소에 올렸다.

## 2차 — 일러스트 스타일 디자인 적용

### 참고한 이미지의 특징
- 색: 남보라 배경, 숲색 둥근 덩어리, 숯색, 주황 손글씨, 산호색, 회보라색
- 장식: 주황색 네 갈래 반짝이 별, 얇게 휘갈긴 주황 선
- 질감: 종이에 그린 듯한 거친 느낌

### 바꾼 것
| 부분 | 전 | 후 |
|---|---|---|
| 배경 | 연회색 | 남보라 + 숲색 덩어리 + 종이 질감 |
| 카드 | 흰색 | 숯색에 크림색 글씨 |
| 제목 | 검정 글씨 | 주황 손글씨 글꼴(Jua) + 반짝이 별 |
| 버튼·체크박스 | 파랑 | 주황 |
| 중요도 | 빨강/주황/회색 | 산호/주황/회보라 |

### 진행 방법
- 바꾸기 전 흰 디자인에 저장 지점(`white-design`)을 찍었다.
- 연습장 브랜치(`design-seoul`)에서 작업하고, 마음에 들어서 원본(`main`)에 합쳤다.

## 3차 — 폴더 정리

### 정리 후 모습
```
todolist-1009
├─ docs/      문서 (이 계획서, 되돌리기 안내)
├─ js/        동작 코드 (역할별 5개 파일)
├─ tests/     자동 검사 페이지
├─ index.html
├─ style.css
└─ README.md
```

### 지킨 것
- 앱 동작과 디자인은 그대로. 파일 위치만 바꿨다.
- 더블클릭으로 열 수 있게, "모듈" 방식 대신 `index.html`이 `js` 파일을 순서대로 불러오는 방식을 썼다.
- 자동 검사는 설치 없이 브라우저로 여는 `tests/test.html`로 만들었다.
- 검사는 실제 할 일 목록과 다른 이름의 저장 칸만 쓴다.

### 진행 방법
- 연습장 브랜치(`reorganize`)에서 작업하고, 단계마다 커밋했다.
